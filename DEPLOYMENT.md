# Deployment Guide (Render)

Step-by-step to host this API on [Render](https://render.com).

---

## 0. Before you start — know the free-tier rules

Render's **free tier** is fine for *testing*, but has two limits:

| Resource | Free tier |
|---|---|
| Web service | Spins down after 15 min idle; cold-start ~1 min; 750 hrs/month |
| Postgres | **Expires 30 days after creation**, then deleted unless upgraded |

- For a permanent system, the cheapest **paid Postgres is ~$6/mo** (Basic-256mb).
- For a 30-day test/demo, free is perfectly fine — just re-import data if it expires.
- (Alternatives with *permanent* free Postgres: Neon or Supabase — but Render is
  the simplest all-in-one, so start here.)

---

## 1. Create the service (one click, uses `render.yaml`)

1. Sign up at https://render.com (use your GitHub account).
2. Dashboard → **New +** → **Blueprint**.
3. Connect your GitHub account, then select the repo `zusty-debug/Bd-teacherdb`.
4. Render reads `render.yaml` and shows what it will create:
   - **Web service** `emis-records-api` (Python / Uvicorn)
   - **Postgres database** `emis-records-db`
5. Click **Apply**. It builds and deploys (takes a few minutes).

> Your `MASTER_KEY` is auto-generated by Render (see step 4).

---

## 2. Verify the API is up

1. In the `emis-records-api` service page, copy the URL (looks like
   `https://emis-records-api.onrender.com`).
2. Open `https://<your-url>/health` → should return `{"status":"ok"}`.
3. Open `https://<your-url>/docs` → interactive Swagger UI.

---

## 3. Load your data (the CSV → Postgres)

The database is empty at first. Load the CSV **from the deployed shell**:

1. In the `emis-records-api` service page, open the **Shell** tab.
2. Run:
   ```bash
   curl -o emis_full.csv https://files.catbox.moe/54n9at.csv
   python -m scripts.import_csv emis_full.csv
   ```
3. Wait ~3–5 minutes. It should print:
   ```
   inserted: 396970
   skipped: 0
   institutions: 19106
   unknown_columns: []
   ```

> The shell inherits the `DATABASE_URL` environment variable automatically,
> so the data lands in your Render Postgres.

---

## 4. Get your master key

1. In `emis-records-api` → **Environment** tab.
2. Find `MASTER_KEY` (Render generated a random value). Click to reveal/copy it.

---

## 5. Create your first API key

```bash
curl -X POST https://<your-url>/api/v1/admin/keys \
     -H "X-Master-Key: YOUR_MASTER_KEY" \
     -H "Content-Type: application/json" \
     -d '{"name": "my-first-app"}'
```

→ The response contains the full `sk_...` key **once**. Save it.

---

## 6. Test a query

```bash
curl "https://<your-url>/api/v1/employees?search=ZAMAL&per_page=3" \
     -H "X-API-Key: sk_..."
```

Full endpoint reference: see `API_REFERENCE.md`.

## Troubleshooting

- **App crashes on startup / "Can't load plugin sqlalchemy.dialects:postgres"**
  → already fixed in `app/config.py` (normalizes `postgres://` URLs).
- **"Could not create pg_trgm search indexes" warning in logs**
  → harmless; search still works, just slower.
- **Free service sleeping** → first request after idle takes ~1 min; upgrade to
  paid to remove spin-down.
- **DB expired after 30 days** → upgrade the Postgres to a paid tier, or
  re-create + re-import.
